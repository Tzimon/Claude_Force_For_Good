**Title:** Append -test suffix to push notification topics on test systems

---

### Short description
When `TEST` is enabled, push notifications are sent to `{region}-{language}-{channel}-test` instead of `{region}-{language}-{channel}`. Notifications sent from the test CMS no longer reach users of the production app.

### Proposed changes
- Add `FirebaseApiClient.get_topic()`, which appends `-test` to the FCM topic when `settings.TEST` is true. The format matches the example in integreat-app#3301 (`testumgebung-de-news-test`).
- The `group` field in the data payload is unchanged (e.g. `news`).
- Add a parametrized test for `TEST=True` and `TEST=False`.
- **Separate commit:** make pytest collect `TestFirebaseApiClient` again. The class defined `__init__()`, so pytest skipped it with only a `PytestCollectionWarning`. None of its tests ran, including the topic tests. It now uses a class attribute instead.
- Three of the previously skipped tests no longer matched the current behaviour of `send_pn()`. I adjusted them to the code as it is now:
  - The `200_no_name` test now expects `send_all()` to return `False`. `send_pn()` only returns `True` when the response contains a `name`.
  - The 403 and 404 tests now expect the log message `sent, but unexpected API response` instead of `Received invalid response from FCM for`.

  Please check that treating "HTTP 200 without message name" as a failure is intended. If it isn't, the code should change rather than the test.

### Side effects
- Only test systems are affected (`INTEGREAT_CMS_TEST=True`). Production behaviour is unchanged.
- Test builds of the app need to subscribe to the `-test` topics to keep receiving notifications from the test CMS (integreat-app#3301).

### Faithfulness to issue description and design
There are no intended deviations from the issue and design.

### How to test
- `pytest tests/firebase_api`: 15 tests pass. Before the collection fix, only the 3 `TestFirebaseDataClient` tests ran.
- Without the change in `firebase_api_client.py`, the new test fails for `TEST=True`.
- Manually: set `INTEGREAT_CMS_TEST=True`, send a news item, and check that the topic in the FCM request ends in `-test`.

I also ran the whole test suite locally. The only failures were 83 tests in dashboard, place category, PDF export, region deletion, feedback and API result. They fail the same way on unmodified `develop` in my environment, so they're unrelated to this PR.
