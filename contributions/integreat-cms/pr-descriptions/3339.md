**Title:** Prepend https:// to URL fields without scheme

---

### Short description
Entering a URL without a scheme (e.g. `www.example.com`) into a URL field no longer fails the browser's validation. `https://` is prepended automatically.

### Proposed changes
- New pure helper `addMissingUrlScheme()` in `static/src/js/utils/url.ts`:
  - `www.example.com` → `https://www.example.com`
  - `//example.com` → `https://example.com`
  - Values that already have a scheme are left unchanged (`http:`, `https:`, `mailto:`, `tel:`, …). Dots aren't allowed in the scheme pattern, so `www.example.com:8080` is still recognized as a host with a port.
  - Empty values are left unchanged, so optional fields stay empty.
- New module `static/src/js/forms/add-missing-url-scheme.ts`, imported in `index.ts`. Using document-level event delegation, it applies the helper to every `input[type=url]` that isn't read-only or disabled:
  - on `change`, which fires on blur after the value was edited,
  - on `Enter`, because then the browser validates the field before it loses focus.
- Vitest tests for the helper (12 cases).

### Side effects
- Affects every `type="url"` input in the CMS, e.g. region (Zammad URL), contact, place, event meeting URL, organization, external calendar, and the link checker's edit field. That field also accepts `mailto:` and `tel:`, which are left untouched.
- Server side, Django's `URLField` already adds a scheme. This change only removes the client-side blocker.

### Faithfulness to issue description and design
The issue proposes running the check on blur. I use `change` (which fires on blur when the value was modified) plus `Enter`, so that submitting with the keyboard also works.

### How to test
- `npx vitest run`: all tests pass.
- Manually: open a region form, enter `www.example.com` in the Zammad URL field, leave the field (or press Enter) and save. The value becomes `https://www.example.com` and the form saves.
- `npm run build`, `tsc --noEmit`, ESLint and Prettier pass for the changed files.
